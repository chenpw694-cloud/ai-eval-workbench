# 单机试跑验收记录

本轮用“功能验收 · 两题试跑”验证真实数据链路。三个产品均明确命名为验收产品，上传素材为仓库演示图片；这些记录只用于功能验证，不代表真实竞品结论。

## 自动验证

- `pnpm test`：82 项通过，0 项失败。覆盖评分边界、修订链、备份结构与题库解析。
- `pnpm build`：TypeScript 检查及 Vite 生产构建通过。

## 浏览器实际操作

1. 新建空项目，填写三个产品与版本，手工添加第一题。
2. 导入两题 JSON 时，重复题号阻止整批追加；改为只导入第二题后保存成功。
3. 将计划题量明确设为 2，保存本次试跑的三项边界政策并确认规则。
4. 上传一张原始 PNG，设为最佳图，逐图确认可用性和侵权风险；添加 A-06 / P2，记录耗时 38 秒，保存草稿。
5. 刷新后原图、标签、耗时和备注仍在；正式提交成为第 2 版，题库及规则冻结。
6. 第二题记录 60 秒超时、无输出、G-04 / P1 和失败原因，提交成功。
7. 汇总 A 为 `(3 + 1) / 2 = 2`，B / C / F 为 3。缺少走查、费用或其他产品数据时，总分保持空缺。
8. 提交三个编辑走查、整体体验、零费用和明确标为功能验收的授权检查记录。
9. 从界面导出正式备份：包含 2 题、3 份评测修订、3 条走查、7 份项目快照及 1 个图片内容。独立校验导出文件中的图片 SHA-256 通过。
10. 在另一浏览器源地址的空存储区恢复该备份，界面显示原图与项目完整性检查通过；恢复后将 A-06 从 P2 改为 P3，再次提交成为第 3 版，证明修订链可继续。

两个测试源分别为 `http://127.0.0.1:4173` 与 `http://localhost:4173`，利用浏览器按源隔离 IndexedDB 模拟空设备恢复。它不是三台真实设备的多人同步验收。
