## 浏览器实际操作

使用 `127.0.0.1:4173` 与 `localhost:4173` 两个源的独立 IndexedDB 模拟两份设备存储：

1. 从逐题评测真实保存的 PNG、标签和走查记录生成初评提交包，下载清单及 ZIP。Python 标准库解压和独立 SHA 检查通过。
2. 在两份存储中，分别将同一父修订改成 P1 与 P3，形成明确的判断分叉。
3. 导入预览显示一项冲突，并在选择、裁决成员、依据缺失时禁用确认按钮。
4. 采用导入判断后，原第 3 版保留，新建第 4 版；逐题页正确展示 P1、不可用、原图和裁决备注。
5. 重复导入同一个已裁决包，显示“已导入”，无需重复裁决，确认后不增加收据或评分记录。
6. 只选择清单、漏选 ZIP 时，提示缺失分包名称；没有写入新收据。
7. 导入独立的准备包，在本机创建同 ID 项目，包含 2 题、3 个产品与分工，已提交和出图数量均为 0，规则锁定。
8. 同一个准备包分别导入两份存储，再从其中一份导出带审计的汇总主包，在另一份合入成功。两次独立导入事件的收据并存，不因来源包相同而发生 ID 冲突。

这不是三台真实设备的端到端联调。三人全部 50 题的业务执行、国内网络、公网部署与不同浏览器容量仍需后续验收。

## 当前限制

支持准备包、本人初评包与汇总主包；校准判断、盲复评、正式 GSB 和联合排名尚未接入正式数据链路。成员选择只用于流程署名。数据包检查提供完整性验证，不提供发送人认证或数字签名。

分包与元数据仍有技术上限，详见 [使用说明](08-stage-sync.md)。浏览器存储空间不足时写入会回滚；需保留收到的原包和导出原图。公网网站与 GitHub 仓库尚未创建。
