# 产品定位与首版范围

> 2026-10-22 流程调整：当前采用“每人一个竞品，共用自家基准”，不再要求竞品之间联合排名。当前入口、按组 GSB、报告案例及新旧归档口径见 [最新流程](22-self-comparison-flow.md)。本文其余内容保留对应阶段的设计与验证记录。

## 产品目标

工作台帮助 AI 产品经理与小型团队把产品试用体验转化为有证据、可比较、可复核的评测结论。第一阶段的验收目标是三名评测员能完成本次电商文生图评测、交叉复评和汇总，而不是只展示预填充的界面。

课程作业检验流程是否完整；日常工作要求约束方案与数据能否复用；作品展示要求约束交互、代码、文档和提交记录的质量。用户要求逐步设计，因此当前先完成信息架构和核心流程，关键页面与交互实现仍待后续设计。

## 用户与使用场景

| 使用角色 | 核心工作 | 使用方式 |
| --- | --- | --- |
| 评测负责人 | 整理方案、分配任务、合并数据、组织裁决、导出报告数据 | 负责维护项目主包和发布阶段版本，可兼任评测员 |
| 评测员 | 在外部产品生成图片、上传证据、初评、独立复评 | 各自在浏览器内完成分配的任务，导出提交包 |
| 结果阅读者 | 查看结论、理解差异、追溯样本 | 查看汇总导出或公开演示；实际数据由负责人决定如何分发 |

V1 的身份选择是本地工作流标识，不是账号认证或安全权限系统。静态网站对访客开放，每位访客拥有各自的本地数据，彼此不会自动同步。

## 已采纳的方案

| 事项 | 当前决定 | 原因 |
| --- | --- | --- |
| 交付形式 | 独立开源网页项目，代码归用户账号或组织维护 | 支持公开访问、审阅代码及持续修改 |
| 规则配置 | `schemes/ecommerce-t2i/scheme.json` 与题库文件 | 修改可由 Git 记录，后续方案可新增文件夹 |
| 项目规则 | 创建项目时保存完整规则与题库快照及摘要 | 上游方案更新不会静默改变已有结果 |
| 多人协作 | IndexedDB 本地存储，负责人集中合并数据包 | 先完成本次短周期任务，减少云端搭建依赖 |
| 证据保存 | 保留首次输出全部原图，生成缩略图用于预览 | 支持最佳图复评、可用率核对与图像细节检查 |
| 技术方向 | Vite、React、TypeScript、ECharts；GitHub Actions 与 GitHub Pages | 前端独立开发部署，源码与设计文档一起维护 |
| 逻辑拆分 | 评分引擎、存储、同步、页面分离 | 使计算与数据完整性可独立验证 |
| 后续扩展 | 预留异步存储接口和稳定 ID，再增加 Supabase 协作能力 | 云端仍需补充认证、权限、并发与同步状态设计 |

## 首版功能范围

1. 项目基本信息、产品信息、成员与任务分配。
2. 本次方案预置、配置校验、题库导入，以及规则快照。
3. 校准记录、逐题生成记录、原图上传、最佳图选择、问题标签和存疑备注。
4. 编辑任务走查、整体体验分及产品功能检查。
5. 独立交叉复评、分歧识别、裁决与全量复查任务。
6. 联合排名与直接 GSB，分别保存方法、样本集合及数据来源。
7. 维度分、总分、可用率、净胜率、高频标签与分组表现。
8. 数据包导入导出、合并预览、冲突处理、图片完整性检查与备份状态。

后续扩展包括实时云协作、视频与对话专用评审界面、跨项目分析，以及更复杂的可视化规则编辑。首版配置页优先展示当前有效规则与校验结果，规则文件仍是可追踪的方案来源。

## 本次案例的数据基线

输入依据是用户在对话中的需求，以及《电商文生图产品竞品评测规则文档》v0.1 草稿。用户需求优先于参考文档；文档中指向评测员的操作规则作为产品规则来源使用。

- 项目可配置四个产品：一个模拟自家产品与三个竞品。
- 当前真实执行安排沿用文档的三名评测员、每人负责一个竞品的 50 题。
- 保留四产品与自家对各竞品逐题 GSB 的原始范围：50 题乘以三个产品对，共 150 个直接比较任务。模拟自家的素材与记录标记为模拟；允许在本项目中与同题竞品素材比较，比较集合标记为“含模拟数据”，另行展示。它们不进入真实竞品的推荐排名和真实比较统计。若后续加入真实自家结果，需要明确负责人和生成证据，并配置新的真实比较集合。
- 题目采用四类场景、四类品类、三级难度；实际 50 道题尚未提供，不能将占位题或演示题视为真实完整题库。
- 本次采用七个一级维度、25 个标签。标签先换算为每题每个适用维度的分数，再按各维度的汇总方式计算结果。
- 直接 GSB 与抽选 12 题的联合排名是不同方法，分别展示，不能合并分母。

## 首版验收原则

评测员能从任务进入一题，保存图片与判定，再导出可恢复的数据包；负责人能合并三人的记录，保留独立初评与复评，并导出基于真实数据的结果。

未评测、未提交、规则不适用和已评测无问题必须是不同状态。未填写的数据不能自动获得 5 分，缺失的产品、成本或对比记录不能以模拟值补齐正式报告。

导入重复包不增加题数；冲突不静默覆盖；缺图可被定位；换设备可从完整备份恢复；新增上游方案版本不会重算旧项目。

## 后续需要补齐的输入与口径

| 事项 | 当前状态 | 在流程中的处理 |
| --- | --- | --- |
| 三个竞品的名称、档位、访问方式及负责人 | 尚未确认 | 创建项目时可保存草稿，开始校准前补齐 |
| 完整 50 题与参考图 | 附件仅给出规范与三道示例 | 导入并检查分布后再发布正式任务 |
| 自家产品素材来源与对比分工 | 需求描述为模拟自家，尚未提供同题素材 | 保留 150 个模拟自家对竞品的 GSB 任务，补齐素材与分工后执行；如范围变动需显式调整任务计划 |
| 四个真实产品时速度与成本的排名换算 | 文档只定义三产品 5、4、3 分 | 当前正式三竞品沿用原口径；扩展真实集合前确认新规则 |
| 失败、零输出、零可用图及并列速度/成本的计分 | 草稿未完全定义 | 评分实现前确认，未确定时显示缺口，不输出完整正式总分 |
| F-01 的发生比例 | 文档阈值按评测图片计，逐题标签仅针对最佳图 | 配置阶段明确逐图计数或补充风险计数，不能用最佳图数量冒充全部图片数量 |
| 质量差异中 P0/P1 的比较口径 | 文档未详列标签集合与等级变化的对应关系 | 详见复评设计中的工作口径，正式执行前冻结 |
| 交叉复评的维度范围 | 图像证据不能直接复现完整操作体验 | 本稿建议逐题独立复评 A、B、C、F；G 如需复评须另有可重放操作证据，配置阶段确认 |
