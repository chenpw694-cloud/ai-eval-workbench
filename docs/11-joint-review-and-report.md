# 联合排名、报告草稿与交付检查

后续第 12 轮已新增固定版本归档，见[版本归档与离线复核](12-version-archive.md)。本文记录第 11 轮及独立报告工作区的草稿导出行为。

本轮完成正式项目的“联合排名”“报告与检查”，并提供不依赖本地项目 UUID 的独立演示入口 `#/report`。演示所有产品、图片、数值与判断均为模拟；其中商品素材重复使用，只用于检查布局与交互。此页面操作保留在组件会话，刷新或离开页面后恢复示例，不写入正式项目数据库。

## 联合排名

初评全部有效提交后，成员共同选择同一批样本。默认按电商方案四场景各三题；品类与难度显示在选择卡片上，必须记录共同选题依据。`scheme.json` 中的 `jointReview` 声明场景、每场景配额及正式最小题量。旧项目未含该字段时使用相同默认值，不改写原规则哈希。

- 样本固定后保留题号、真实产品集合、初评修订、最佳图 ID 与 SHA-256；界面读取最佳图时再次检查字节摘要。模拟自家不混入真实联合排名。
- 三个产品最佳图并排，支持相同名次。名次为 1 到产品数的整数，至少一个第一名；是否跳名不影响两两相对顺序，不使用名次绝对值计算分数。
- 需要全体已配置成员确认参与，并记录共同判断依据。“无法判断”必须说明原因，保留记录但排除分母。
- 两两净胜率为 `(左方胜 − 左方负) / 有效题数`；平局计入分母。它与自家对竞品的 GSB 分开展示。
- 修改排名追加修订，原排名不可覆盖。相同父版本分叉、同 ID 异内容或不同固定样本不能静默合并。
- 原初评出现新修订时仍保留历史证据，并显示过期提示；不会自动用新图替换旧图。当前尚不支持给已有固定计划重新建立联合样本，确需更换证据时应另建项目。
- 默认题库不足 50 题、任一场景不足 3 题时明确标为试跑，不能通过正式联合评审完成检查。小项目可按各场景实际题量完成操作演练。

这里是三人共同讨论界面，提交前不展示原维度分。成员可能已经看到初评或讨论，不能据此声称实现了盲评或身份认证。

## 报告工作区

三种视图：报告预览、撰写结论、交付前检查。

人工撰写核心结论、产品优势与短板、自家启示、联合和维度结果的差异解释、功能与授权检查、局限。典型案例从固定联合样本中选择 3–5 组。带备注的最新初评逐条确认，并填写处理说明；新增初评修订需要重新确认。

结论可分次保存，追加不可变草稿修订。未保存输入不进入预览或导出，导出按钮在未保存时禁用。产品级功能检查目前是人工文字摘要，不是完整结构化检查表。

统计可选原始初评与裁决口径参考分；不会改写原始一致率。联合结果与完整总分的领先方向相反时提示人工解释，不自动写推荐理由。缺完整总分的产品不进入自动推荐列表。

导出文件：

- **Markdown**：方法、权重、七维得分和覆盖数量、分场景 A/B/C/F、联合两两结果、原始一致率、GSB、高频逐题标签、人工结论、案例证据 ID/摘要、局限及全部检查项。
- **JSON**：以上指标，另含按品类与难度分组、完整缺口、产品/规则/题库快照、所用初评/独立判断/裁决引用、联合计划及最近排名、最近结论修订。

场景、品类与难度分组仅计算可从逐题图像判断获得的 A/B/C/F。D、E 和 G 含产品级操作信息，不冒充按场景重新计算的综合总分。图像维度排除零输出时，各组保留实际计入数量和计划题量；没有有效记录时显示空值。

Markdown 中典型案例目前是证据引用，不内嵌图片；本轮也未生成打印版 PDF、图文报告或报告雷达图。

## 检查范围与归档边界

检查覆盖配置、真实产品初评/走查/费用/授权依据、校准及锚点、复评和裁决、触发全量复查、最终引用、旧基线、联合场景配额、已配置自家的 GSB、备注、人工结论、案例及修订结构。

未配置自家时，GSB 明确标为不在当前三竞品报告范围；不能将其视为原四产品方案已经完成。无法判断不被补成平局或满分。模拟比较单列。

**所有输出始终标为报告草稿，不会设置项目已归档。** 原图备份项保留待处理：Markdown 与报告 JSON 没有原图字节，不能仅凭元数据声称备份成功。应另在“阶段同步”导出汇总主包并保存清单和全部 ZIP；其导出与导入会逐图校验。

联合排名、报告结论和历史修订已经纳入正式 JSON 备份及完整阶段主包，可恢复和合并。独立盲评包继续物理剔除联合讨论和报告结论。

第 11 轮当时尚未完成：报告与原图主包的一次性最终归档、可审计的项目完成状态、完整结构化功能检查表、报告 PDF/图片嵌入、规则自动迁移，以及 GitHub 与公网部署。当前检查页不是完整归档协议的实现。

## 本轮验证

- 自动测试：190 项通过，0 失败；生产构建与 TypeScript 检查通过。其中新增 19 项覆盖联合配额、并列/无法判断、修订和分叉、试跑、过期基线、备注重新确认、否决隔离、最终引用、报告分组及完整 ZIP 往返。
- 浏览器演示：实际修改一题排名，A 对 B 的净胜率由 12.5% 变成 0%，旧排名保留为两版；保存报告备注处理后相应检查关闭。
- 正式数据区：在明确标记的两题功能验收项目中固定样本、提交三产品并列第一、保存部分报告草稿；刷新后排名和结论仍存在，保持试跑和草稿标识。
- 实际下载 Markdown 与 JSON，解析检查演示标识、草稿状态、最新结论、净胜率与 150 条初评引用；图片字节不在报告文件中。
- 50 题演示为合成数据，并非三人已完成真实评测；正式多人多设备协作仍需要用实际课程素材联调。
