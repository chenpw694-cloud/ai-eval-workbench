# 编辑走查：可选步数与定位提示

“请填写三个任务的操作步数”原来会拦住整页提交，而且只显示短暂提示，用户不知道是哪一项缺失。操作步数没有参与 D 分数公式，却被当成了全部走查的有效性前置条件。

当前行为：

- 三个任务的操作步数均选填。空白保存为 `null`，表示未知，不自动填 0；明确填写时仍须为非负安全整数。
- 任务结果、D 问题标签及锚点分仍按已有规则检查。未完成目标不能借助留空步数作为无问题提交；仍需记录相应 D 标签和原因。锚点评分仍需实际选择 1–5 分。
- 提交检查统一列出问题，显示具体任务名称或字段。错误任务有标记和内联说明；页面下方提示可点击定位，提交时也定位第一项。
- 草稿仍能保存未完成的任务，但不接受负数、小数或无效步数。
- UI 与计算逻辑共用 `validateWalkthrough`，避免页面允许提交而计算仍将 D 排除。

新固定归档使用 `report-v4`。`report-v1/v2/v3` 继续使用原先步数必填的校验口径，重新核验旧归档不会使缺失数据突然获得分数。原字段结构、已有非空步数、评分与权重不变。

验证包括：空白、0、正整数、负数、小数、非有限值；标签与锚点两种口径；未完成任务及缺少 D 锚点；新归档往返与旧 v3 固定报告的缺分保留。浏览器合成项目验证了小数的任务定位、三项空白提交、刷新持久性和实际 D 分计入。
