# 阶段同步与数据包协议

状态：完整目标协议的设计稿。本轮只实现准备分发、初评提交和汇总主包，采用独立 `.eval.json` 清单与原图 ZIP 分包；具体使用方式和当前边界见[阶段同步使用说明](08-stage-sync.md)。下文的校准、盲复评、正式 GSB 与最终质量归档仍是后续设计，不能将本稿视为已全部实现。

V1 为静态网站与 IndexedDB，各人独立保存记录，负责人作为唯一正式合并点。网站不传输团队数据；代码、规则及模拟示例可公开，真实记录与原图不提交 Git。

## 1. 同步节点与交付

三人各负责一个真实竞品的 50 题；保留第四个模拟自家及其对三个竞品逐题比较的 150 个 GSB 任务。模拟自家标为 demo，可在本项目形成“含模拟数据”的比较集合，但不计入真实排名、真实净胜率或真实一致率。自家素材及 GSB 分工尚待补齐。

| 节点 | 输入与目的 | 负责人输出 |
| --- | --- | --- |
| 准备分发（非一次结果同步） | 完整 50 题、产品、成员、分工、初始规则 | 同一项目基础包；固定 ID、题库与规则快照 |
| 第 1 次：校准 | 5 题 × 3 产品的 15 组首次生成图；三人各独立判断，共 45 份，讨论尺度差异 | 校准裁决、案例与修订记录；冻结正式规则快照，分发正式任务包 |
| 第 2 次：初评完成 | 每产品 50 题、3 个走查任务、整体体验分、功能检查及全部原图 | 正式基线包；每产品随机 10 题的定向盲复评包；每场景 3 题、共 12 题的联合排名任务 |
| 第 3 次：质检完成 | 30 份复评、12 题联合排名、分歧裁决；模拟自家 GSB 单独标识 | 已裁决主包、完整性报告、真实与含模拟的分项汇总；若触发复查则输出补评任务 |

校准原图计入对应题目的首次输出，不重新生成。45 份校准判断保留为独立记录；产品负责人按正式规则提交自己产品的初评记录，引用原图，不把三人的校准判断重复计入 50 题。各评测员平时也可随时导出备份；界面显示上次成功备份时间及之后新增的数据量。

校准首次生成时同步记录耗时、失败状态、所有输出及费用归属，正式阶段直接引用，避免补造操作数据或重复计费。

## 2. 数据包组成

采用 ZIP，内含 `manifest.json`、`project.json`、`records/` 与 `images/`；缩略图用于预览，原图全量保留。清单声明每张原图的哈希、大小、类型及引用关系，并标明基础包、提交包、盲复评包或正式主包。

- 包：`schemaVersion`、`packageId`、创建人、阶段、来源主包版本、文件哈希清单与适用范围。
- 项目：`projectId`、产品/成员/分工、规则快照及 `schemeHash`、题库快照及 `questionsHash`，真实与 demo 标识。
- 记录：稳定 `recordId`、题目/产品/评测员 ID、`phase`、`revision`、`parentRevision`、作者、提交状态、原图哈希引用及业务字段。

复评、校准、初评、裁决使用独立记录类型和 ID。草稿可修改；已提交版本不可原地改写，修订生成后继版本。裁决引用原判断并写明理由、参与人及最终采用版本，保留完整历史。时间戳仅供追溯，不决定哪条意见生效。

## 3. 导入与合并

1. 先校验 ZIP、清单及 schema，再比对项目、规则、题库和分配范围。
2. 展示预览：新增、重复、冲突、缺图、缺任务及 demo 数量；用户确认后才写入。
3. 无冲突记录按修订链接入；同一包或同一记录版本重复导入不重复计数。相同哈希的图片只存一份，并保留所有引用。
4. 同一记录从同一父版本产生不同后继，或父版本缺失，列为冲突；并排展示差异，由负责人选择版本或形成有理由的新修订，不按“最后修改时间”覆盖。
5. 校验及冲突处理完成后事务写入；失败回滚，原库保留。导入报告记录包 ID、结果及负责人处理意见。

规则哈希不同不能直接合入正式结果：校准后的迁移由负责人显式确认，保留旧快照与判断，要求按新规则重新提交适用记录。正式开评后的口径调整另建规则修订及影响清单，不静默重算已归档结论。

## 4. 复评可见性与归档条件

第 2 次同步的完整主包仅由负责人持有。复评包只包含指定 10 题的需求、参考图、验收点、原图和原最佳图标记，排除初评标签、分数、可用张数、裁决及可能泄露判断的备注；复评人提交后才揭示差异。联合排名先提交名次，再查看原维度分。若负责人兼任复评员，主包先在汇总空间暂存，预览仅显示数量及完整性；从暂存数据生成定向包，在独立浏览器配置中提交复评后，再显式查阅原评分。离线工具无法证明其未主动读取本地数据。

抽样记录随机种子、抽样方法、候选集与基线版本；复评期间不随意替换样本。任一维度相差至少 2 分，或 P0/P1 标签判定不一致，记该题不一致。每产品分别以 10 题计算；超过 3 题不一致时，发起该产品全部 50 题复查，导入补充包并完成裁决后才允许归档。

上述维度指任务声明的复评范围；本稿的建议范围和 P0/P1 细化口径见[评审可见范围](03-review-visibility.md)，正式执行前冻结。一致率取原始独立判断，不取裁决后共识。

归档还需检查：真实产品各 50 题已提交、走查及检查项齐全、原图引用完整、存疑和冲突已处理、复评与排名完成。模拟自家图与相关 GSB 仅进入明确标识的“含模拟数据”输出；若其 150 个比较任务仍在计划中，整体归档也要求完成，或由负责人显式修订任务范围。可先导出三个真实竞品的分项报告，但不能据此将整个项目标为已完成。分工与本地成员选择属于流程约束，不是账号认证或安全权限。

## 5. 错误恢复与验收

| 场景 | 预期结果 |
| --- | --- |
| 重复导入；三人按不同顺序提交 | 数量不增加；无冲突数据汇总一致 |
| 导错项目、题库或规则版本 | 拒绝写入并说明差异，保留当前数据 |
| 缺图、文件损坏或哈希不符 | 阻止正式导入，列出缺失项，重新导出后重试 |
| 两台设备修改同一父版本 | 进入冲突处理，双方判断及原图均保留 |
| 不兼容 schema、空间不足或写入中断 | 拒绝或回滚；保留原包，可在兼容版本导出升级后重试 |
| 导入盲复评包及最终主包 | 提交前看不到原判断；揭示后可追溯，原分不被覆盖 |
| 产品复评恰为 3/10 与 4/10 不一致 | 前者完成逐题裁决；后者触发 50 题复查并阻止归档 |

存储接口采用异步调用，业务逻辑不依赖 IndexedDB；以后云协作还需新增身份、权限、并发和同步机制，不能只替换适配器。
