# 正式项目：单机采集、评分与完整备份

> 本文保留上一轮单机功能的使用记录。当前已增加初评阶段包、ZIP 分包与负责人合并，分发或开始评测后即冻结口径；最新流程与边界以 [阶段同步说明](08-stage-sync.md) 为准。

本轮把正式项目从演示工作台中分出，支持一台设备、一个浏览器配置中的真实数据采集与本地计算。原图和记录实际写入 IndexedDB，正式结果来自项目自身的数据，而非演示看板的预置统计。

目前没有账号认证、实时共享或跨人合并。三人完整协作、校准包、独立复评包、正式 GSB、联合评审及裁决仍属于后续阶段。原演示工作台保留相应交互示例，但其记录不会自动转成正式结论。

## 1. 入口与数据区

在演示工作台点击“进入正式项目”，或打开运行地址后的 `#/projects`，进入本机正式项目列表。可新建正式项目，也可恢复正式完整备份。

正式与演示数据区分开。新建正式项目会提供本次七维度、25 个标签的基础方案，以及待补充的成员和产品信息；不会复制演示题、商品图或虚构分数。

本轮验收中使用的“验收产品”和两道题，仅用于验证功能链路，不代表已经完成真实竞品评测。开始课程评测前，需要提供真实产品名称、版本或会员档位、负责人、完整 50 题、参考图及实际输出。

## 2. 配置项目与题库

在“项目与题库”填写项目背景、周期、成员、产品角色、产品版本与负责人。CSV 可使用空模板，也可映射自定义列名；JSON 使用标准题目结构。题目支持手工维护，额外字段随题保留。批量导入有错误时先显示问题，不写入部分成功的题目。

正式发布前需满足项目名称、有效成员与负责人、真实产品及版本、需求描述和至少一条验收要点等校验，并确认规则。七个一级维度权重总和必须为 100%。

**计划题量是正式任务范围。**

- 计划 50 题但只导入 2 题，可以保存配置和采集草稿，不能正式提交，也不会得到完整总分。
- 需要两题独立试跑时，先把计划题量明确改成 2，再完成两题配置并正式提交。
- 首个正式提交后，规则、题库、计划题量、成员及产品身份被冻结。已正式试跑的两题项目不能再追加成 50 题；完整评测需另建项目。
- 费用与商用授权等后续采集信息仍可补充。评分记录修订另存，原提交保留。

题目中的参考图文件名只是引用。要求参考图的题目，必须在逐题评测中上传同名参考图；校验会按项目、题目和精确文件名匹配。

## 3. 单题采集与修订

在“逐题评测”选择产品、题目和评测员，在外部产品完成生成后上传首次输出的全部原图。逐张填写是否可用、是否存在侵权风险，再选择最佳图，为最佳图记录 A/B/C/F 问题标签，为过程记录 G 标签。默认等级可在允许范围内上下调整一级，F-01 固定为 P0。

每次记录还需生成耗时；失败时必须写原因，并记录 G-03 或 G-04。非失败任务必须有输出图，最佳图必须属于本题本产品，图片检查不能留空。存在侵权风险的图片不能标为可用；最佳图存在 A/B/C/F 的 P0/P1 问题时也不能标为可用，G 过程标签不会直接改变图片可用性。

草稿允许暂存未完成内容。正式提交同时检查项目准备情况、规则与题库快照、原图归属和逐图检查，不能通过直接进入评测页绕过准备校验。

修订使用父版本引用保留历史。最新修订为草稿时，旧提交不会继续冒充当前完成结果；重新提交后使用新版本。分叉或版本关系异常会成为缺口，不静默选取一个版本。

## 4. 走查、费用与正式评分

在“走查与成本”记录换背景、改颜色、扩图三项任务的步数、完成状态与 D 标签，补充整体体验分、总费用和商用授权判断。总费用未知为缺失，明确填 0 才表示免费。

“实际得分”按以下来源计算：

| 维度 | 计算方式 |
| --- | --- |
| A/B/C/F | 每题该维度取最高严重等级换算分数，再求有效题目均分 |
| D | 三项有效走查的 D 标签分均值 |
| E | 可用率子分 50%＋速度排名子分 25%＋单张可用图成本排名子分 25% |
| G | 逐题 G 标签均分 50%＋整体体验分 50% |

无标签只在有效且已提交的判断中记为 5 分。未交、缺图、未检查、快照不匹配均保留缺口；有参考均分时也标明覆盖数量，只有七维度都完整且权重有效才计算总分。

方案中需明确三种边界口径：失败零输出可保留图像维度缺口、图像维度记 1 分，或显式排除有效图像分母。选择排除且全部零图时，有效分母为 0，效果均分为空；选择记 1 分时属于明确规则分，并非图片表现观察。全部零图都没有图片可用率，不能输出完整总分。并列速度/成本可暂留缺口，或按连续档位计分，例如 5、5、4。零可用图成本可暂留缺口，或仅将 E 的成本子分记 1 分，不做除零计算。

真实产品的速度与成本排名需要全部真实产品完成所需数据。模拟产品单独计算，不改变真实排名。侵权比例按全部输出的逐图检查计数，达到 5% 即否决，不能只数最佳图的 F-01 标签。商用明确不允许或不明确时否决，尚未检查则待定；否决产品可保留得分参考，但不具备推荐资格。

## 5. 完整备份与恢复

“项目备份”导出正式 JSON，包含项目配置、规则与题库快照、评测修订、图片清单与原图内容、走查和整体体验记录。原图按摘要校验；缺图或校验失败时不能冒充完整备份。正式备份与原演示 JSON 是不同格式。

当前完整备份适用于**项目图片清单中原图合计不超过 75 MB**的小批量闭环，含参考图和输出图。原图编码进 JSON 后，文件体积会增加；当前恢复文件上限为 110 MB。超过当前容量的完整项目归档需要后续 ZIP 分包，本轮没有实现。

恢复先检查结构、快照摘要、图片内容及引用关系，再整体写入。目标浏览器中必须尚不存在该项目 ID；同 ID 已存在时拒绝恢复，不覆盖、不合并。验证恢复可使用尚未存有该项目的独立浏览器配置。正式备份不能作为三个人的提交包互相导入。

## 6. 本地保存的边界

IndexedDB 属于当前浏览器配置和当前 origin，即协议、主机、端口的组合。不同设备、浏览器、浏览器配置，以及 `localhost` / `127.0.0.1` 或不同端口不会自动共享项目。代码上传 GitHub、页面部署成功，也不会同步本地评测数据。

换设备或切换运行地址前应导出正式完整备份。清除站点数据会移除本地保存内容；本轮没有服务器副本或后台自动备份。保存草稿、正式提交和导出文件是不同动作，未保存的编辑不包含在备份中。

当前正式能力可完成小批量采集、七维度评分和恢复验证。完整三人、50 题、多产品评测仍需后续跨人阶段包与合并机制；正式 GSB 和质量控制工作流也尚未接入。
