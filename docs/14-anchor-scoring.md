# 1～5 分锚点直评分

## 从哪里进入

- [公开交互演示](https://chenpw694-cloud.github.io/ai-eval-workbench/#/anchors)：侧栏“锚点打分”，可选择整数分、选填依据、保存演示草稿。数据保存在独立演示区，不进入正式报告。
- 正式项目：**项目与题库 → 规则确认 → 评分方式与锚点 → 锚点直评分（扩展口径）**。确认规则并保存后，在“逐题评测”右侧评分。

原课程文档要求评测员打标签、系统换算得分。新增加的是可配置的扩展口径，不能将两种方式的结果当作同一轮规则比较。默认仍为原标签换算；未声明评分方式的旧项目也沿用原规则。

开始评测、分发或创建质检后，评分方式、锚点、权重与规则快照一起冻结。已有标签项目继续使用原口径；如需锚点评分，另建项目。不会将旧标签记录自动补成直接评分。

## 评分范围

| 维度 | 入口与口径 |
| --- | --- |
| A / B / C / F | 逐题评测，按固定最佳图选择 1～5 分整数，评分依据选填；产品维度分取有效题均值 |
| G | 逐题记录实际操作过程的锚点分；与“走查与成本”的整体体验分各占 G 的 50% |
| D | “走查与成本”的三个编辑任务分别按锚点选分、选填依据；取三项均值 |
| E | 继续按可用率、速度与成本计算，不用主观分覆盖实际指标 |

输入只允许 1、2、3、4、5，没有 0 分或半分。维度均值、E 的合成分以及加权总分可以出现小数，报告与实际得分页面对锚点项目使用 **5 分制**。标签项目保留此前的百分制总分展示。

逐题必须补齐 A/B/C/F/G 的 1～5 分整数才可提交；各维度评分依据均选填，无问题时可直接留空。草稿可不完整；未选择的维度显示“待评分”，不以无标签补为 5 分。单题原始评分与依据保留在不可变评测修订中，修订、交接和归档使用现有机制。

失败且零输出时，A/B/C/F 遵循项目确认的“记 1 分 / 排除 / 保留缺口”政策，无须对不存在的图片编造评分；G 仍需评价实际失败过程。D 仍需记录完成情况与步数；未完成时须记录 D 问题标签和原因。

## 标签与风险

锚点模式下，问题标签用于诊断、问题统计及风险检查，不换算维度分。逐图可用性、侵权风险和商用授权仍需独立检查；F 的人工高分不能取消原有否决条件。最佳图有图像维度 P0/P1 标签，或 A/B/C/F 任一直接评分不高于 2 分，均不能标为可用。

A-03 / B-01 的特殊情形说明默认收起为“标签等级说明（选读）”，不作为报错，不会仅因勾选这些标签就强制改为 P0 或要求填写备注。实际存在可用性冲突时，界面与提交校验共用同一判断函数，显示具体标签或低分维度；不再把仅有低分的情况误报成 P0/P1 标签问题。评测员可定位到“逐图检查”，或明确点击“将最佳图标为不可用”；系统保留评分与标签，不自行更改评测结论。

提交失败时，评分栏自动显示并聚焦实际错误，逐条提供字段定位入口。所有修改留在页面，草稿仍可保存。合成项目验证了 A-03 P1 与“可用”冲突后的定位、修正及成功提交，以及 A-03 P2、空备注、可用图片正常提交；原有锚点分和标签等级保持所选值。

## 配置与复评

`schemes/ecommerce-t2i/scheme.json` 的 `rating` 保存默认评分方式及六个主观维度的 1～5 分描述。每个维度需完整、唯一的五档描述；项目开始前也可在配置页编辑锚点，编辑会取消规则确认。项目保存的是规则快照，页面编辑不会直接修改仓库文件。

独立校准、复评和裁决同样使用该项目的 A/B/C/F 锚点。任一维度相差至少 2 分，或 P0/P1 编码与等级集合不一致，记为不一致。定向任务包剔除原始评分和依据；返回包只含自己的独立修订。裁决参考口径使用裁决的图像维度分，G 保持初评；原始评分和原一致率不会被改写。

## 文件版本与兼容

- 标签项目继续使用阶段包和完整 JSON 备份 schema 1；旧归档的 `ecommerce-v1` 计算口径保留。
- 锚点项目的阶段包与完整 JSON 备份使用 schema 2；新版本可读两种格式，旧工作台会拒绝新格式，避免忽略直接评分后错误按标签算分。团队成员领取锚点包前应刷新页面到新版。
- 锚点归档声明 `calculationVersion: ecommerce-anchors-v1`，总清单仍为 schema 1，内部主包为 schema 2。核验时要求评分方式与版本相符，重算报告并比对文件。
- 新归档标记 `reportVersion: report-v2`，评分依据允许留空；无该字段或标记 `report-v1` 的旧归档，仍按当时的必填校验和报告原文核验，避免改写冻结结果。当前工作项目统一使用依据选填规则，不需要迁移项目配置或重新确认规则。
- Markdown 报告说明评分口径，并列出逐题直接分与已填写的依据；JSON 报告及原始主包保留结构化数据。
