# 逐题采集与题库图片引用

本轮修复针对两个实际阻塞：当前题被其他空白产品的名称、版本拦住，以及 JSON 的 `ref_images` 数组被当作不支持的额外字段拒绝。

## 采集可以分次完成

- 问题标签按实际问题选择，没有发现问题可以全部留空。标签规则项目正式提交后，无标签的维度按既定规则计 5 分；锚点项目的标签只用于诊断，分数仍需单独填写。
- “保存草稿”留在当前题；“保存草稿并下一题”保存尚未完成的记录并继续。草稿不计为正式完成，不会因为没有填分而被补成满分。
- “提交并下一题”只检查当前产品的名称、版本、负责人及当前题证据，不要求其他产品先填完。项目结构、题库计划、规则确认和评分证据校验继续生效。
- 单张输出自动选为最佳图；多张输出需人工选择。逐图可用性、侵权判断、耗时以及适用的锚点评分仍在正式提交时检查。
- 错误提示使用产品名称或列表序号，并说明去哪里补齐；不再显示难以识别的产品 UUID。

项目开始或分发后，产品名称、版本/会员档位、竞品角色、负责人和成员显示姓名仍可更正，保存后也可继续编辑。成员及产品 ID、增删范围、真实/模拟属性、题库、计划题量和评分规则保持冻结，不能通过退回草稿绕过。存储事务与界面执行同一规则；已填写的名称/版本不能保存为空，负责人须为现有项目成员。

团队分发、质检、报告及归档继续检查完整配置。其他产品未配置时，当前题可以显示“已提交”，结果汇总仍提示配置缺口；补齐配置后重新计算，无需重新提交原有评分。

## 评测开始后更正成员姓名

在“项目与题库 → 项目与分工 → 评测成员”直接修改现有成员姓名，并点击成员区下方或页首的“保存配置”。姓名不能为空；增加、删除成员仍锁定。保存产生新的项目快照，旧快照保留原姓名，评分、图片、成员 ID 和题库/规则摘要均不改写。

阶段包按成员 ID 判断关联，姓名差异不会阻止旧包合并；已有项目合并时保留本机更正后的姓名，不用旧包覆盖。姓名不是登录账号或权限。

验证：已开始且已有正式提交的三成员合成项目中修改三个姓名，保存、刷新与导出后姓名保留；比较备份确认全部评测记录、素材元数据、成员 ID、产品分工及规则/题库摘要相同，历史快照保留原姓名。自动测试覆盖更名、空姓名拒绝、增删/换 ID 拦截和旧阶段包兼容。

## 产品信息保存后继续更正

在“被测产品与负责人”中直接编辑名称、版本/会员档位、竞品角色与负责人，再点“保存配置”。这四项仅在保存期间暂时停用，保存完成和刷新后继续可编辑，不再按“原字段是否已填”锁定。

更正产生新的项目快照。历史初评、图片及原评测员 ID 不改写，负责人更正不会把旧评分改署到新负责人。旧阶段包按原包快照核对发送人负责范围，合入时保留本机更正后的产品信息；变更产品 ID、真实/模拟属性、题库或规则仍视为不兼容。

验证：已开始且已有提交的三产品合成项目中，连续两次修改四个字段，保存、刷新后均保持可编辑；导出核对评分、素材、产品 ID、题库/规则摘要完全一致，历史保留两次产品更正，原评测员仍为旧署名。测试覆盖角色/负责人有效性、空字段拒绝和旧产品信息阶段包兼容。

## JSON 图片字段

标准 `referenceNames` 与常见字段 `ref_images`、`referenceImages`、`images` 都支持文件名、数组及含 `name`、`filename`、`fileName`、`path`、`url`、`src`、`data`、`dataUrl` 的图片对象。例如：

```json
[
  {
    "id": "Q-001",
    "request": "将参考商品制作成纯白背景主图",
    "acceptance": ["商品完整", "背景纯白"],
    "ref_images": [
      "R01_精华液.png",
      { "filename": "R01_侧面.png", "caption": "保留瓶身比例" }
    ]
  }
]
```

本地文件名会进入参考图匹配列表；带目录的本地路径按文件名匹配。图片对象、URL、嵌入来源和附加说明保存在“更多题目字段”，不会丢失或覆盖原有同名备注。

**导入图片引用不等于上传图片文件。** 题库导入不会读取电脑上的路径、请求外部链接或把来源文本当成本地原图；实际素材继续通过逐题评测页上传，随项目备份与阶段包传递。URL 来源不会被错误列为必须上传的同名文件。

241 项自动测试与生产构建通过，覆盖图片字段兼容、来源保留、任务与汇总校验范围、冻结配置的安全补齐。浏览器使用独立合成数据项目验证：导入三题、上传参考与输出、单图自动最佳、零标签提交、其他产品空白时提交成功、未完成题保存下一题、刷新恢复，以及提交后补齐原空白产品身份。
