# AI 产品评测工作台

[在线体验](https://chenpw694-cloud.github.io/ai-eval-workbench/) · [正式项目入口](https://chenpw694-cloud.github.io/ai-eval-workbench/#/projects) · [源码仓库](https://github.com/chenpw694-cloud/ai-eval-workbench) · [MIT 许可证](LICENSE)

面向 AI 产品经理与小型团队的可配置人工评测工具。首个落地案例是三人共同完成电商文生图竞品评测，随后再扩展其他 AI 产品类型。

当前版本已支持**真实采集、本地正式评分、阶段同步、校准/独立复评/GSB、联合排名、报告草稿与固定版本归档**。从演示界面的“进入正式项目”打开独立数据区，新建项目后填写产品与版本、导入题库、上传首次输出并记录判断；在“阶段同步”分发准备包、提交本人初评或导出汇总主包。**源码已上传 GitHub，公开网站已部署至 GitHub Pages。**

原有入口保留为界面演示，GSB、联合排名及演示裁决仍可体验；其预置题目、统计和商品素材不代表真实产品表现。正式项目另有“质量控制”，支持固定校准、交叉复评、全量复查、GSB、独立任务包和质量裁决。另有“联合排名”及“报告与检查”，支持固定同题样本、共同名次、报告结论和缺口检查。另有“版本归档”，支持阶段快照、条件齐全后的最终归档和整组文件复核。

## 1～5 分锚点打分

打开[锚点打分演示](https://chenpw694-cloud.github.io/ai-eval-workbench/#/anchors)可直接体验选分和保存。正式使用时，在“项目与题库 → 规则确认 → 评分方式与锚点”选择“锚点直评分”，确认并保存规则，再到“逐题评测”填写分数与依据。输入统一为 1～5 分整数，汇总使用 5 分制。D 在编辑走查中打分，E 仍由实际指标计算。已开始评测的项目保留原口径，需新建项目采用另一种评分方式。

详见[锚点直评分与数据兼容](docs/14-anchor-scoring.md)。

## 当前可以完成什么

- 项目冻结后可“重新开始”创建可编辑的新草稿，默认清空题库重新导入，也可保留题目；旧项目及评分素材保持原样。
- 项目可移入本机回收站并随时恢复；项目列表与配置页均有入口，旧标签页不能继续写入回收站项目。
- 配置项目、成员、产品名称与版本、计划题量及规则；通过 CSV / JSON 导入题库，或手工维护题目。
- 保存原始输出与参考图，逐图检查可用性和侵权风险，选择最佳图，记录标签、等级、耗时及失败原因。
- 保存草稿、保存草稿并下一题、提交初评并保留修订历史；无问题时标签可不选，其他产品的空白配置不再拦住当前题。补齐三项编辑走查、整体体验分、费用与商用授权判断。
- 按七个维度计算实际得分、覆盖数量、可用率和否决状态；缺少数据或口径时保留缺口，不补成满分。
- 通过清单与 ZIP 分包传递原图；预览新增、重复、阻断和冲突，确认后事务写入，保留同步收据及双方原记录。
- 导出不含评分的准备包、限定所选成员负责产品的初评提交包，以及携带历史审计的汇总主包；主包包含原标签和判断，不能用作盲复评包。
- 定向分发实际剔除原判断的独立包，保存原始一致率与 GSB；裁决、最终引用和裁决口径参考分分开保留。
- 四场景各三题的联合评审、并列排名、两两净胜率、不可变排名修订；结论可分次保存，导出 Markdown 草稿和 JSON 明细，保留缺失项与证据引用。
- 报告、主包和原图一起生成固定版本文件组；校验后留存只读归档，继续评测不会覆盖旧版本。完整配置前的草稿仍用普通项目备份。
- 原有正式 JSON 完整备份仍可导出与恢复，原图合计上限为 75 MB，恢复不做项目合并；日常团队协作使用阶段包。

计划 50 题但只导入 2 题时，不能正式提交或分发。若要独立试跑两题，先将计划题量改为 2；开始评测或分发后，题库、计划题量、成员、产品身份和规则被冻结。尚未分发的项目可补填原空白的产品名称或版本；已有值保持锁定。完整 50 题评测应另建项目。[阶段同步使用说明](docs/08-stage-sync.md)列出了三人操作步骤与本轮边界。

JSON 题库兼容 `ref_images`、`referenceImages`、`images` 的文件名数组与图片对象。来源与附加说明会保留，实际图片文件仍在逐题页上传。详见[逐题采集与题库图片引用](docs/15-flexible-collection.md)。

试填后需要重新导入题库，打开“项目与题库 → 重新开始 → 清空题库，重新导入 → 创建新草稿”。旧项目可以保留或移入回收站；恢复入口在“我的项目 → 回收站”。详见[项目重新开始与回收站](docs/16-project-lifecycle.md)。

## 本地运行

使用 `.node-version` 声明的 Node.js 24.19.0，以及项目声明的 pnpm 11.25.0。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的本机地址，默认是 `http://127.0.0.1:4173/`。正式项目入口为 `#/projects`，独立评审空间为 `#/projects/independent`。直接查看归档演示用 `#/report?view=archive`，全局归档校验入口是 `#/projects/archives`。查看报告/联合排名界面演示用 `#/report`，不需要先在当前浏览器创建项目。

数据保存在当前浏览器配置、当前 origin 的 IndexedDB。协议、主机或端口变化会进入不同数据区，例如 `localhost` 与 `127.0.0.1` 不共享数据。换设备或浏览器需主动传递阶段包或恢复完整备份；代码仓库和静态网页本身不保存评测数据。

阶段包由一个 `.eval.json` 清单和全部 ZIP 分包组成，默认每包目标 40 MiB、单包硬上限 50 MiB；原图按 SHA-256 去重。当前还设有单图 25 MiB、清单 10 MiB、最多 256 个分包及原图总量 8 GiB 的技术上限，**这些上限不表示已完成同规模压力验证**。

```sh
pnpm test
pnpm build
```

`pnpm test` 运行 `tests/*.test.mjs`，覆盖评分、缺失数据、修订、题库导入、存储、备份、分包校验和合并规划。构建结果位于 `dist/`，Vite 使用相对资源路径与 hash 导航，为后续部署 GitHub Pages 保留兼容性。不要直接以 `file://` 打开源码 HTML。

## 已确定的产品方向

- 先支持本次真实评测，兼顾作品展示和后续继续 vibe coding。
- 独立开源项目，仓库归项目所有者维护。
- 在线页面为主要入口，表格用于题库导入与数据导出。
- 方案以仓库内 JSON 配置保存；项目绑定规则和题库快照。
- 当前使用本地存储，三人通过文件交接，由负责人集中合并；后续再接云端协作。
- 真实数据与模拟演示数据分开，原始出图随评测记录归档。

## 后续实施方向

当前使用 Vite、React、TypeScript、ECharts，正式评分和合并规划纯函数与界面分离，本地存储使用 IndexedDB。GitHub Actions 已实际完成测试、构建与 Pages 部署。下一步开展三人试评，再补结构化功能检查、图文报告与更大数据规模的验证。

代码已包含 `schemes/`、`src/core/`、`src/storage/`、`src/demo/`、`src/pages/` 与 `docs/`。当前验收使用的产品名称与两题记录仅是功能测试数据，并非真实竞品评测；开展课程评测仍需填写真实产品与版本，准备完整 50 题、参考素材及各产品的实际输出。

项目采用 [MIT 许可证](LICENSE)。公开站点使用明确标记的合成演示素材。真实评测记录和原图保存在本地及导出的数据包中；公开仓库包含源码、方案、设计文档和获准公开的演示数据。


阶段同步上一轮验收：146 项测试与生产构建通过，已验证 80 MiB 分包和浏览器冲突合并。具体范围见[阶段同步验收记录](docs/09-stage-validation.md)。

质量流程本轮验收：171 项测试与生产构建通过。已实际验证独立复评回收、50% 原始一致率保留、裁决参考分、GSB 平局分母和双向空间隔离；详见[质量流程及验证说明](docs/10-quality-workflow.md)。

联合排名与报告阶段验收：190 项测试和生产构建通过；已验证实际排名修订、正式存储刷新恢复、报告下载与数据包往返，见[功能和边界](docs/11-joint-review-and-report.md)。工作区报告为草稿；后续版本归档可冻结符合条件的最终报告。

锚点评分更新：支持配置锚点、正式初评、独立复评、裁决、分组报告与版本归档；沿用旧标签规则的项目及 `ecommerce-v1` 归档保持兼容。新锚点项目使用 schema 2 数据包。
